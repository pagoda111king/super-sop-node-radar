# Scoring Rubric

Scores are evidence-backed aids for decision-making. They are not final truth.

Use 0-5 for each dimension.

| Dimension | Question |
|---|---|
| node_fit | Does it directly support the target node job? |
| maturity | Is it stable enough for repeat use? |
| activity | Is the project actively maintained? |
| integration_surface | Does it expose CLI, SDK, API, MCP, or skill-friendly interfaces? |
| local_testability | Can we test it locally without heavy setup? |
| enterprise_fit | Does it support auth, permissions, deployment, and compliance needs? |
| evidence_quality | Are claims backed by docs, code, releases, and tests? |
| maintenance_burden | How expensive is it to keep using? Reverse score: 5 means low burden. |
| risk | What is the residual risk? Reverse score: 5 means low risk. |

## Score Bands

| Average | Meaning |
|---|---|
| 4.5-5.0 | strong candidate for approval after tests |
| 3.5-4.4 | useful, but scope carefully |
| 2.5-3.4 | experimental or niche |
| 1.5-2.4 | weak fit |
| 0.0-1.4 | do not use |

## Required Comment

Every score must explain:

- why the score was given
- what evidence supports it
- what test could falsify it
